# Read-only Nuke DAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Vite + React component that parses a Nuke `.nk` or `.gizmo` script and draws its node graph read-only, matching Nuke's DAG closely enough that a compositor recognizes the script.

**Architecture:** A pure TypeScript parser turns the TCL-like script into a group tree and a connection stack. A pure layout pass assigns Nuke's top-left coordinates, class colors, label-driven sizes, and pipe anchors. A TypeGPU renderer draws that scene as real 2D on a WebGPU canvas: orthographic DAG pixels, rounded rectangles and circles via signed distance in the fragment shader, cubic pipes stroked into 2D triangles, and text from a glyph atlas. React owns pan, zoom, selection, and stepping into groups. Nothing is a Three.js mesh or a DOM node per Nuke node.

**Tech Stack:** Vite, React, TypeScript, Vitest, `typegpu`, `unplugin-typegpu`. Package manager: pnpm.

## Global Constraints

- Vite is the bundler and dev server. Do not use Webpack, Parcel, Next, or CRA.
- Draw with TypeGPU on WebGPU as real 2D. No Three.js, no perspective camera, no CSS/SVG/HTML node graph.
- `'use gpu'` functions must be compiled by `unplugin-typegpu` in `vite.config.ts`.
- The public component is `NukeDag` in `src/NukeDag.tsx`. Props are exactly `script: string`, optional `className`, optional `style`, optional `onSelectNode?: (node: DagNode | null) => void`.
- Read-only. No knob editing, no dragging nodes, no writing `.nk`.
- `xpos` / `ypos` are the top-left of the node in DAG pixels. Y grows downward. Foundry's own center is `xpos + screenWidth/2`, `ypos + screenHeight/2`.
- Default node body is 80×18 DAG pixels for one line of text. Extra label lines add 12 pixels of height. Horizontal padding is 8 pixels each side. Dots are 12×12.
- Connection stack: a node pops one stack entry per input, first pop is input 0, then the node is pushed. `inputs` omitted means 1, except the script almost always writes `inputs 0` for generators. `inputs N+M` is N main inputs plus M mask inputs (total popped = N+M). `push 0` pushes a null input. `set NAME [stack I]` stores that stack slot without popping. `push $NAME` pushes the stored node, or null if the name is missing. Several `push` calls may share one line.
- Do not push `BackdropNode` or `StickyNote` onto the connection stack. Do not push `Root` or `LiveGroupInfo`.
- Input 0 is the rightmost of the top splay (Nuke's B). Input 1 is to its left (Nuke's A). The first four main inputs splay across the top. Further main inputs stack down the left edge. Mask inputs (`+M`) sit on the right edge. A single main input is top-center. Output is bottom-center. A dot's input and output are its center.
- `tile_color` wins over the class default. It is `0xRRGGBBAA` or a decimal integer of that same 32-bit layout. Dots with no `tile_color` inherit the first non-dot upstream color.
- Group, Gizmo, LiveGroup, and VariableGroup are one node in the parent. Their interior is a nested graph between the node body and `end_group`. Double-click enters it. A breadcrumb leaves it.
- `clone $NAME { ... }` copies that node's class and knobs, then applies the brace overrides, and is flagged as a clone.
- Parser and scene code must not import `typegpu` or React, so Vitest can run them in Node.
- Do not copy source from `maxWiklund/nuke_parser` or any other viewer. The behavior above is the spec. Write original code.
- TypeScript strict. No `any`. No `as any`.
- Tests assert real outputs. A test that only checks "does not throw" is not sufficient on its own.

- [ ] **Step 3: Implement the parser**

Character scanner, not a line regex. Brace depth and quotes must stay in sync.

Statement level, skipping whitespace and `#` comments that start a line outside strings:

- `version <rest of line>` records the version text.
- `set <name> [stack <index>]` stores `stack[length-1-index]` without popping. Index 0 is the top.
- `push 0` pushes null.
- `push $<name>` pushes the stored node or null.
- `end_group` closes the current group frame.
- `clone $<name> { knobs }` copies class and knobs from the stored node, deletes nothing the brace sets, parses the brace with the knob reader, builds the node, wires inputs, pushes it.
- `<Ident> { knobs }` builds a node. Ident may contain dots (`OFXuk.co.thefoundry...`).

Knob reader inside a body: depth starts at 1. Read an identifier key, then a value. A value starting with `"` reads until the closing quote, honoring backslashes, and may span lines. A value starting with `{` reads until that group's braces balance, and the stored string includes the outer braces. Any other value is the rest of the line, trimmed. Decode `\\`, `\"`, and `\n` in quoted strings only.

Input count: omitted knob → `{ main: 1, mask: 0 }`. `N` → `{ main: N, mask: 0 }`. `N+M` → those numbers. Pop `main + mask` entries, first pop is input index 0. Then push the node unless its class is `BackdropNode`, `StickyNote`, `Root`, or `LiveGroupInfo`.

Group classes `Group`, `Gizmo`, `LiveGroup`, `VariableGroup` open a new frame after the node is linked in the parent. Nodes until `end_group` are their children and use the inner stack. The inner stack starts empty.

Ids: `root/<name>` at the top, and `<parent.id>/<name>` when nested. Names come from the `name` knob or `${className}${counter}`.

`define_window_layout_xml` is parsed with the same brace reader and discarded.

Unknown statements: if the next token is not a known keyword or `Ident {`, skip the line. Do not throw on a missing variable.

Bounds: union of node rectangles, expanded by 40. Empty graph bounds are `{0,0,1,1}`.

- [ ] **Step 5: Implement the atlas and the renderer**

`textAtlas.ts` rasterizes glyphs on a 2048×2048 canvas with `48px Verdana` (so zoom-in stays sharp) and records metrics in CSS pixels of that font. `measure` for layout must still be 11px Verdana, exposed as `measureDagText(line: string): number` using a small canvas. `GlyphLookup.measure` is the 11px measure. Quads in geometry are in DAG pixels; the atlas UVs are independent of size. Scale the 48px glyph box into the requested DAG height.

`renderer.ts`:

- `await tgpu.init()` and `root.configureContext({ canvas, alphaMode: "premultiplied" })`.
- One camera uniform: origin `vec2f`, scale `f32` (device pixels per DAG pixel = `zoom * dpr`), viewport `vec2f` in device pixels.
- Vertex buffer of the `Vertex` struct. Recreate or write it in `draw` when the scene or the zoom band changes. Pan only updates the uniform.
- Vertex shader maps DAG position to NDC:

```
screen = (dag - origin) * scale
ndc.x = screen.x / viewport.x * 2 - 1
ndc.y = 1 - screen.y / viewport.y * 2
```

- Fragment shader: mode 0 returns the vertex color. Mode 1 and 2 compute a signed distance (round rect, circle) and antialias with `fwidth`. Mode 3 samples the atlas and multiplies alpha by the vertex color. No depth buffer. Blend `src-alpha` over `one-minus-src-alpha`.
- Clear color `[0.110, 0.110, 0.110, 1]` which is `#1c1c1c`.
- `resize` sets `canvas.width` and `canvas.height` to css size times dpr and updates the context.
- `draw` no-ops when the device is lost. `destroy` destroys the root.
- If `navigator.gpu` is missing, `createNukeRenderer` rejects with `Error("WebGPU is not available")`.

Read the installed `typegpu` typings and match them. Keep the clear color, the NDC formula, the four modes, and the blend mode. Do not add a render loop.
